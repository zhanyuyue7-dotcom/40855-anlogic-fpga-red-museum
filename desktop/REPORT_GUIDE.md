“测试档案 / 历史回放”从 `report_data/manifest.json` 加载。当前默认展示**最终提交版本约72小时长稳实测**，完整日志与重算结果已归档。

- 测试总览：5,184,000条状态，首末跨度259,196.911649秒，存储故障状态记录0。
- 历史记录回放：默认选择最终版本72小时记录，显示完整日志中每3,600条抽取一条及末条，共1,441个真实快照；趋势图为4,320个分钟窗口的图片索引变化次数，累计57,937次。
- 完整CSV导出：顺序读取完整压缩日志，导出全部5,184,000条状态及原时间戳、来源和SHA-256。输出文件较大，导出在后台线程执行。
- 旧M5两小时、M3场景及时序修复窗口仍可单独选择；事件延迟页继续引用原M3的4个事件，不与新长稳混算。
- “72h实测 / 历史计划”显示已完成结果，同时保留原8/24/72小时组合场景容量预算。原计划空结果字段不代表当前长稳尚未完成。
- “设计优化与实现”保留历史报告数值并明确来源；当前冻结构建指标以 [验证说明](../docs/验证结果与边界.md) 为准。

完整数据入口见 [数据来源索引](../数据来源索引.md)，测试说明见 [72小时实测归档](../datasets/measured/long-run-72h-20261028-1031/README.md)。音频和自动轮播并非全程开启，故障状态记录0不扩写为物理零丢包或全程音画验收。

在根目录执行 `py -3.12 tools/sync_long_run_archive.py` 可重新生成回放抽样、分钟统计和当前测试CSV；`desktop/build_report_dataset.py` 在此提交目录也转到同一同步入口。构建EXE时 `build_windows.py` 会包含完整72小时压缩日志。源码直接运行依赖相邻的 `datasets/`，请保留整个提交目录。

历史测试 CSV 快照保存在 `../datasets/test-cases/`；当前 GUI 从 `report_data/manifest.json` 加载档案。
